# Roadmap

One milestone at a time. Draft, 29 Oct 2026. The starting point is the Journey Together Companion for Discord
(`JourneyTogetherForever/companion`, commit f70d781): its reader, webhook, game finding, settings, window, picture
drawing and installer move here and lose everything that is Journey Together's.

| # | Milestone | Check |
|---|---|---|
| W1 | **The framework** (built 29 Oct 2026). The Companion's code moved here, the app renamed. Data plugins found in AddOns folders and read from `webhooks.json`; the outbox (`docs/PLUGINS.md` §3) read for every used plugin; kept and news kinds posted per channel, group and kind; no backlog; the window with Addons, groups and kinds from plugins; settings in `%APPDATA%\WoW Addon Webhooks for Discord`. Tests with a sample plugin and a fake Discord. | A sample plugin and a sample SavedVariables file: the window lists them; a test channel gets a kept message (edited on the next save) and each news item once |
| W2 | **Journey Together as a plugin** (built 29 Oct 2026; in the Journey Together repository): the addon writes `JourneyTogetherForeverDB.webhooks`; `Webhooks/webhooks.json`; the board page as `card.html`; pictures from `Media` (the app reads TGA). The Companion's game folder and choices carried over (§9 of the spec). The Companion code and `board` table removed from the addon. | A logout updates the board in Discord; a clear and a chapter post once each; nothing from the Companion's channels is posted twice |
| W3 | **Flows** (built 29 Oct 2026; its check done by hand against a local fake Discord the same day, not yet against the real one; SPEC §5.1–5.3, §8): the Flows page replaces Discord channels. A canvas with the addons as a tree on the left (plugin → groups, with Every {group} first → kinds), channels on the right, and steps in between, joined by dragged lines; Connect to… and Remove menus for the keyboard; Tidy up; the flows in words under the canvas. The steps Mention a role, Digest, Quiet hours and Into a thread; a forum channel gets a forum post per item by itself. The weekly summary as a kind in the tree (the former W3: `numbers` and the manifest's `weekly`). Setup's step 3 becomes the canvas. Choices from W1–W2 become lines. | Journey Together's kinds drawn to three channels: the board in #progress, Chapter complete in #progress with a mention and in #events without, clears in #events, pictures in a daily Digest in #screenshots. Each arrives once where it should; quiet hours hold a post until they end; a forum channel gets one post per clear; a pretend week (the app's clock moved) posts one summary per group; done with the keyboard only as well |
| W4 | **Only if, and screenshots** (built 29 Oct 2026; tried by hand against a local fake Discord the same day): the plugin names fields per kind (`fields` in the manifest, `fields` on news items, `docs/PLUGINS.md`); the Only if step filters on them. A news item with `screenshot` (when the game took it) gets the game's screenshot from that second attached, found in the game's Screenshots folder (read only). Journey Together writes the fields its kinds need (chapter number, dungeon, who). | "Chapter is at least 5" lets chapter 5 through and holds back chapter 4; "Who includes Lea" lets only her clears through; a picture taken with Take a picture arrives in #screenshots with the screenshot itself, also in a Digest |
| W5 | **Flows in two columns** (decided and built 29 Oct 2026; SPEC §5.1, §5.2, §8): no step boxes. What an addon posts on the left, channels and their threads on the right, one line per flow. Rules on the line: Only when (several values with commas), Mention a role (with a name for the app), Gather into the daily post; on the channel: quiet hours, the daily post's time, threads. A line's settings show What Discord shows with the newest saved item, rules applied. Lines carry tags naming their rules. W3–W4 flows become lines. | A new player connects one webhook and presses Post without touching anything else; the W3 check done again with lines only; a W3 setup with steps opens as lines that post the same |
| W6 | **Game art** (decided and built 30 Oct 2026; SPEC §7.1): the game's own pictures, read from the player's game by file id (Blizzard's storage in its Data folder, read only, never encrypted files) and kept as PNG per build. A template asks with `ctx.game(id)`; a news item's `picture` may be `{ game, crop, aspect }`. Journey Together names each dungeon's loading screen, as the game crops it. | The board shows The Deadmines' and Wailing Caverns' loading screens on retail, and a clear of them posts one; a file the game does not have is left out; nothing is written in the game's folder |
| W7 | **Code plugins** (built 30 Oct 2026; its check done on the bench against a local fake Discord the same day; SPEC §3, §6): Install a code plugin… with the warning, the sandboxed script, Remove. | A sample code plugin from a `.zip` posts; one that tries the network, Node.js or runs too long is stopped and named |
| W8 | **Release** (built 30 Oct 2026; the installer built and installed locally, its check mode run on the real Journey Together save; the first tag and the update to the next wait for the public repository; SPEC §10, PLUGINS §8): installer and updates from this repository's Releases, README for players and for addon developers, the developer check mode (`docs/PLUGINS.md` §8). | A tagged release installs, finds Journey Together and updates itself to the next tag |
| W9 | **Guild Hall plugin** (in its repository, when Guild Hall reaches G8): the Herald's addon writes the outbox; `#stocks`, `#arena`, `#hall-of-fame` kinds. | Guild Hall's news reaches its three channels through flows; Journey Together keeps working beside it |
